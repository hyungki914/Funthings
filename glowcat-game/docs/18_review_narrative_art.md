## 1. 항목별 상세 (근거 명시)

### 1-1. 서사 일관성 — 8.5
- 개정 축('왜 잊었나'→'어디 있나')이 데이터에 실제 반영됨: `LBL` slot4 = `'하루는 어디에'`, `LBLN` = `'하루는 어디에 — 갑자기 멀리, 아직 돌아오지 않은'` (data.js 270–271). 추적·희망의 축으로 일관 이동 성공.
- 핵심 개정 챕터 4·9·10 모두 죽음 이미지 제거 확인: `c_haru_bottle` "챙길 새도 없이, 하루는 그렇게 실려 갔다"(data.js 342), epiphany4 "들것에 실려 떠났다 … 돌아오지 않았을 뿐이다"(360–362). '떠났다/사라졌다(영영)' 금지어 규칙 준수.
- **잔존 리스크 1**: data.js 주석 헤더(5번째 줄)에 여전히 `01_story_script.md §2` 구판을 참조. 12_story_10stage.md 구 '회귀 엔딩/약병/죽음' 서술은 15번 문서가 대체한다고 명시됐으나 구 문서 자체는 미수정 → 신규 합류자가 구 canon을 읽을 위험.
- **잔존 리스크 2**: chapter1·2의 `identityLabels`는 인라인으로 `'왜 잊었나'`가 **그대로 남아 있음**(data.js 202, 259). chapter3 이후만 `LBL` 상수(`'하루는 어디에'`)를 씀. 즉 **1·2장만 구 카피, 3장부터 신 카피** — 같은 플레이 안에서 slot4 문구가 '왜 잊었나'→'하루는 어디에'로 바뀌는 비일관. 개정 문서 E)의 지시("LBL/LBLN slot4 교체")가 1·2장에 누락 적용됨.

### 1-2. 회상·깨달음 글쓰기 — 8.5
- "1~2문장, 신파 자제, 사물의 상태로 보여줌" 원칙 충실. 예: `e_park_leaf` "떠나지 못해서가 아니라 — 여기서 다시 만날 것 같아서였다"(data.js 595)는 톤 개정의 정수를 한 문장에 담음.
- false 8종 전부 "이건… 진짜가 아니야"로 닫힘(data.js 169,249,306,347,349,395,443,546,597,642) — 규칙 100% 준수.
- 깨달음 점층 구조(4~5비트, 마지막에 희망 한 발)가 챕터마다 안정적. 10장은 최종 선택 직전 5비트로 짧게 끊어 호흡 좋음.
- 약점: hidden echo(각 챕터 1개, `echo_window`/`c2_memo`/`e_park_leaf` 등)는 최고 수준 문장이 많은데 '기억 비추기(Q)'로만 노출 → 다수 플레이어가 못 볼 가능성. 좋은 글이 묻힌다.

### 1-3. 캐릭터 감정 설득력 — 8.0
- 지로: 1인칭 감각 묘사가 일관("나는, 고양이다" c2_blanket / "코를 묻으면 아직 옅게 하루의 냄새" e_haru_sweater)로 종(種)적 시점이 살아 있음.
- 하루: 항상 사물·흔적으로만 등장(약병, 스웨터, 적립카드 "다음에 같이 받자, 지로"). 절제 톤엔 맞으나, **직접 목소리가 c_blank_promise "…밥 잘 챙겨 먹고… 금방 올게" 단 한 번**이라 재회 엔딩에서 갑자기 또렷해질 때 정서적 적립이 약간 부족.
- e_blank_pov(하루 시점 역샷)가 쌍방향 그리움을 만드는 영리한 장치 — 다만 hidden이라 핵심 반전이 가려질 위험(1-2 약점과 동일).

### 1-4. ★ 랜덤 배치 ↔ recall 불일치 — 3.0 (치명)
- **근거**: main.js 16 `let RANDOMIZE = true;`. `loadStage`→`makeLayout`(114–142)이 도달가능 타일 풀을 셔플(120)해 **모든 shard의 `tile`을 재할당**(127 `{ ...s, tile: [...] }`)하면서 `recall`·`id`·`type`은 보존. 즉 텍스트와 좌표의 결합이 끊긴다.
- **증상 예**:
  - `c2_photo` recall="**소파 위에 걸린 액자**"가 주방 바닥·식탁 옆 임의 타일에 출현.
  - `c_haru_bottle` "**머리맡** 약병"이 방 중앙에, `c_park_bench` "벤치. 우리가 매일 함께 앉던 자리"가 분수 뒤에.
  - data.js의 정교한 좌표 검산 주석(64–89행 "게임기 앞 floor" 등)이 런타임에 **전부 무효화**됨 — 문서와 실제가 따로 논다.
- **심각도**: 이 게임의 핵심 루프가 '사물을 발견→그 사물에 얽힌 기억'인데, 사물과 위치가 어긋나면 **각 조각의 디제시스(공간 서사)가 매번 깨진다.** 몰입형 내러티브 게임에서 가장 비싼 종류의 버그.
- 적 patrol도 동일하게 무작위화(139–140)되나 이쪽은 텍스트 종속이 없어 무해.

## 2. 강점 5

1. **톤 개정의 데이터 정합성** — '실려 감/돌아오지 않음' 어휘와 false 클로징 규칙이 chapter4·9·10 데이터에 실제 반영, 죽음/재회 모순이 거의 없음.
2. **절제된 글쓰기** — 사물 상태로 정서를 보여주는 원칙을 거의 모든 recall이 지켜 신파 회피, 문장 밀도 높음.
3. **시각 모티프 일관성** — 지로 실루엣+눈 발광이 13장 전부에 적용되고 컬러 내러티브(식음→데움→그린/시안 만개)가 코드로 구현됨.
4. **음악 엔진·테마 설계** — 음역 분리·크로스페이드·종지 설계가 정교, 두 엔딩 테마가 각 결말의 정서를 정확히 결산.
5. **두 엔딩의 대등한 존엄** — 재회/길고양이 둘 다 비극이 아니며, 길고양이 엔딩이 '하루의 물그릇 계승' 모티프로 회수되어 선택의 무게가 동등.

## 4. 우선순위 개선안 (문제 → 근거 → 구체안)

### P0-A · 랜덤 배치와 recall 불일치 해소
- **문제**: 공간 서사가 매 플레이 깨짐(가장 비싼 결함).
- **근거**: main.js 116·120·127 — tile 재할당 시 recall 보존.
- **구체안(권장 = 하이브리드)**:
  1. **core는 고정, echo/false만 랜덤**. core는 가구 종속 서사의 앵커이므로 원본 tile 유지; 리플레이성은 echo/false 위치 셔플로 충분. → `makeLayout`에서 `if (s.type === 'core') { shardsOut.push({...s}); continue; }` 한 줄로 분기. **최소 변경·최대 효과.**
  2. (보완) **core recall을 위치 비종속으로 리라이트**할 경우의 예시:
     - `c2_photo`: "소파 위에 걸린 액자" → "**빛바랜 액자 하나.** 나와 하루가 나란히 앉아 웃고 있다."
     - `c_haru_bottle`: "머리맡 약병 하나가" → "**약병 하나가** 뚜껑도 닫지 못한 채 넘어져 있다."
     - `c_park_bench`: "벤치. 우리가 매일 함께 앉던 자리" → "**닳은 나무 자리 하나.** 우리가 매일 함께 머물던 곳."
  3. 둘 중 **1)을 1차 적용**(코드 1줄, 안전), 2)는 echo까지 완전 랜덤을 원할 때 추가. 정합 회귀를 막으려면 data.js 좌표 검산 주석에 "core만 유효" 단서 추가.
