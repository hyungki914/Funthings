## 1. 항목별 상세 평가

### 1-1. 첫 3분 온보딩 — 7/10
- **강점**: `INTRO`/`overlayIntro()`(main.js:66-72, 790)의 콜드오픈 독백이 동기를 부여하고, 빈 방에서 길을 잃는 문제를 직격하는 **L 코치마크**(`drawGuide` main.js:1083)가 무입력 3초·코어 0개 조건으로 등장한다. **직감(H)**(main.js:545-549)은 위치를 스포일하지 않고 "무엇을 할지"만 알려주는 좋은 절충.
- **약점**: 플레이 진입 직후 상단 STAGE 라벨(main.js:1054) + 목표 배너(1060) + 문 화살표 + 좌상단 코어/빛/추적/일지 4줄(1027-1035) + 하단 조작 힌트(1101) + 토스트가 **동시에** 뜬다. 첫 16초 동안 텍스트 7~8개가 경합 → 신규 플레이어 시선 분산.
- 토스트가 좌상단에서 코어 카운터·빛 게이지와 같은 영역(ty=92부터, main.js:1076)을 침범해 겹쳐 읽힌다.

### 1-2. 키보드 조작감 — 8/10
- **모범**: `CODEMAP`(main.js:221)이 `e.code` 기반이라 한글 레이아웃(ㅈㅁㄴㅇ)에서도 WASD가 동작. `GAMEKEYS` preventDefault(main.js:233)로 스페이스 스크롤·탭 포커스 이탈 차단. `cv.focus()` + tabindex(main.js:7)로 포커스 확보.
- 8방향 정규화(main.js:421)와 충돌 분리 이동(`moveAxis` main.js:579)으로 벽 슬라이드가 자연스럽다.
- **약점**: 메뉴/선택지에서 화살표·WASD는 되지만 **ESC로 일시정지(설정) 진입 불가** — 플레이 중 ESC가 동작하지 않는다(`update`의 play 분기엔 escape 핸들이 없음). 일시정지·재맵핑 메뉴가 아예 없다.

### 1-3. 터치/태블릿 조작감 — 4/10 (최약점)
- **강점**: 좌측을 누른 위치에 조이스틱이 생기는 동적(dynamic) 조이스틱(`onPointerDown` main.js:312, `onPointerMove` 323)은 아날로그 입력까지 지원해 감각이 좋다. 자동 감지(`navigator.maxTouchPoints` main.js:242 + `pointerType==="touch"` 시 강제 ON main.js:272)도 합리적.
- **치명적 약점(근본 원인)**: `touchButtons()`(main.js:245-255)가 `bx = W - 66`, `by = H - 70` 기준 **절대 px 오프셋**으로 6개 버튼을 손수 배치한다. 캔버스는 1056×672 고정이고 CSS만 `max-width:100%`로 축소(index.html:13)되므로, 작은 창에서 캔버스가 줄면 버튼의 내부 px 좌표는 그대로 → **시각적으로는 작아져 손가락보다 작아지고, `l`(추적, by-84)·`shift`(은신, by-100) 등 위로 솟은 버튼이 다른 HUD와 겹치거나 잘림**. 세이프에리어/노치 고려도 없음.
- 버튼 반지름이 33~41px(캔버스 px)로, 1056폭이 모바일에서 ~360px로 축소되면 실제 ≈11~14px → Apple HIG 44pt·Material 48dp 최소 터치 타깃에 한참 미달.
- 배치가 부채꼴로 불규칙(라벨 6개)해 블라인드 조작 학습이 어렵다.

### 1-4. 메뉴 흐름 — 8/10
- 타이틀(`overlayTitle` main.js:1121)에 처음부터/이어하기(해금 시)/스테이지 선택 3버튼, 호버 효과음(`onPointerMove` main.js:320)까지 갖춤. 선택 화면(`overlaySelect` 1142)은 키아트 그리드 + 시작/시퀀스 다시보기로 풍부.
- 흐름 타이틀→선택→플레이→일지(Tab 토글)→깨달음→분기/최종선택→엔딩→타이틀/선택이 빠짐없이 닫혀 있다(엔딩 main.js:983에서 Space/Tab 분기).
- **약점**: 타이틀에서 "아무 키/빈 공간 클릭 = 처음부터"(main.js:279)가 이어하기 의도와 충돌할 수 있다 — 이어하기 버튼을 노린 탭이 빗나가면 새 게임이 시작될 위험.

### 1-5. 정보 가독성 — 5/10
- HUD(`drawHUD` main.js:994)는 패널 배경으로 대비를 확보했고 발바닥 메모리 미터는 테마와 잘 맞는다.
- **과부하**: 좌상단 한 패널 안에 코어 카운터·빛 게이지·"[Q]비추기·[H]직감"·"[L]발자국 추적"·"[Tab]기억 일지" 5줄(main.js:1027-1035). 상단엔 STAGE 라벨 + 목표 배너 + 점 진행도 + "빛나는 기억에 다가가 [E]"까지. 동시에 직감 메시지(0.6화면 높이)·토스트·코치마크가 더해지면 텍스트 레이어가 5겹 이상.
- 색약 관점: 코어=시안/거짓=골드/위험=빨강/긍정=연두를 **색만으로** 구분(journal.js 범례 "● 코어/에코/거짓" 529-531, 적 시야콘 보라↔빨강). 모양·아이콘 보조가 부족.

### 1-6. 접근성 — 2/10
- GDD(`docs/13_level_design_10stage.md`)에 색약/플래시 등 의도가 언급되나, 코드에는 **음소거(M, main.js:553)만 존재**. grep 결과 colorblind/textScale/reduceMotion/enemySpeed/difficulty/photosensitive 구현 0건.
- **플래시 리스크**: 피격 시 전체 화면 빨강 플래시(`flash` main.js:731) + 화면 흔들림(`shake`), 심장박동, 추격 드론이 끌 수 없다 → 광과민성 안전장치 부재.
- 텍스트 크기 조절·적 속도(난이도) 옵션 없음. 캔버스 전부 그리기라 OS 폰트 확대도 무력.

### 1-7. 스테이지 장소 안내 — 8/10
- 진입 시 대형 장소 카드(`overlayStageCard` main.js:829, 2.6초 페이드)와 플레이 중 상단 상시 "STAGE N. 장소명"(main.js:1054), 선택 화면 챕터별 키아트 썸네일(main.js:1155)로 "지금 어디인가"가 일관되게 전달된다.
- 사소한 약점: 장소 카드와 방 진입 veil 페이드(main.js:79)가 겹쳐 첫 0.5초 타이포가 어둠에 묻힐 수 있음.

### 1-8. 저장/이어하기 — 6/10
- `loadProgress`/`saveProgress`(main.js:61-63)로 `clearedMax`만 localStorage 저장 → 이어하기·해금 동작.
- **약점**: (1) 스테이지 **도중 진행은 저장 안 됨** — 길게 끄면 처음부터. (2) `RANDOMIZE=true`(main.js:16)라 매 진입마다 배치가 바뀌어 "이어하기"가 같은 상태 복귀가 아님. (3) `SAVE_KEY='ziro_progress_v1'` 단일 슬롯, 데이터 깨짐 시 폴백만 있고 사용자 리셋 UI 없음.

## 2. 강점 5

1. **IME 무관 키 입력** — `e.code` 기반 CODEMAP + preventDefault(main.js:221-234). 한글 환경 웹게임의 흔한 함정을 정공법으로 회피.
2. **진단형 길안내 2단** — 위치를 안 알려주는 직감(H)과 흔적을 그리는 발자국 추적(L)으로 "빈 방 문제"를 스포일 없이 해결(main.js:466-472, 545-549).
3. **동적 가상 조이스틱** — 누른 자리에 생성되는 아날로그 조이스틱(main.js:312-324). 고정 패드보다 손 위치 자유롭다.
4. **서사 연출 완성도** — 콜드오픈→회상→깨달음 몽타주→마음 분기→엔딩까지 풀스크린 키아트·점 진행도·스크림으로 영화적이며 흐름이 닫혀 있다.
5. **일지의 정보 설계** — `journal.js`의 초상 진화(?→실루엣→눈→얼굴→이름), 잠금/해금 시각 구분, 말줄임(`ellipsize`), 여정 스트립까지 한 화면에 잘 압축.

1. **(P0) 터치 스킬버튼 절대 px 고정** — 반응형/세이프에리어 부재로 작은 창에서 잘림·미니어처화(main.js:245-255, index.html:13).

## 4. 우선순위 개선안

### P0 (출시 차단급)

**P0-1. 반응형 캔버스 + 세이프에리어 + 비례 터치 레이아웃**
- 문제: 캔버스 1056×672 고정, 버튼 절대 px → 작은 창 잘림(main.js:245, index.html:21).
- 근거: `touchButtons()`가 `W-66`/`H-70`에 손수 배치, CSS는 max-width 축소만.
- 구체안:
  1. CSS를 `width:min(100vw, calc(100vh*1.571)); height:auto`로 종횡비 유지 + `padding: env(safe-area-inset-*)` 적용(index.html:12-13).
  2. 내부 렌더 해상도를 뷰포트×devicePixelRatio로 리사이즈하고 `resize` 시 `cv.width/height` 갱신(현재 고정). 좌표는 `canvasXY`가 이미 비율 보정하므로 버튼만 비례화하면 됨.
  3. `touchButtons()`를 화면 비율 기반으로 재정의: 버튼 반지름 `r = clamp(W*0.045, 28, 48)`, 우하단 2열 그리드로 **정렬**하고 하단/우측 여백에 `safe-area-inset`을 더한다. 위로 솟은 `l`/`shift` 버튼을 격자에 편입해 HUD 겹침 제거.
  4. 최소 터치 타깃: 실제 표시 크기 기준 44px 이상 보장(축소율 역산).

**P0-2. 접근성 옵션 메뉴 — 최소 구현**
- 문제: 음소거 외 전무, 플래시/흔들림 강제(main.js:553, 731, 614).
- 근거: grep 결과 접근성 토큰 0건; GDD(13번 문서)는 의도만 명시.
- 구체안: 타이틀·일시정지에서 여는 옵션 패널 + `localStorage` 영속. 최소 4토글:
  1. **광과민성(플래시·흔들림 끄기)**: `flash`/`shake` 적용부에 `if(!opts.reducedFlash)` 게이트(main.js:731, 614). 피격은 화면 테두리 펄스로 대체.
  2. **텍스트 크기(중/대)**: 폰트 px에 전역 배율 변수 곱(HUD·배너·회상). 캔버스 렌더라 배율 한 곳에서 관리 가능.
  3. **적 속도/난이도(쉬움)**: `m.speed`·`sightPx`·`hearPx`에 0.8배 옵션(main.js:154-159) — 접근성 겸 난이도.
  4. **색약 보조**: 적 시야콘·조각에 패턴/아이콘 추가(시야콘 빗금, 거짓=◆, 코어=●), 색 의존 제거.
  (볼륨/음소거는 기존 `Audio2.setMuted` 재활용)

**P0-3. HUD 정보 위계 정리**
- 문제: 첫 16초 텍스트 폭주, 좌상단 5줄+토스트 겹침(main.js:1027-1035, 1076-1080).
- 구체안:
  1. 좌상단 단축키 안내 3줄("[Q]비추기·[H]직감", "[L]추적", "[Tab]일지")을 상시 표시에서 제거하고 **첫 등장 시 1회 토스트** 또는 일지 내 도움말로 이전. 상시 HUD는 코어·기억·빛 게이지만 남긴다.
  2. 토스트 시작 y를 게이지 패널 아래로 내려 겹침 해소(ty 기준 재계산, main.js:1076).
  3. 목표 배너의 "빛나는 기억에 다가가 [E]"는 nearShard 근접 시에만 노출(이미 태그가 월드에 있음, main.js:680) — 상단 중복 제거.

### P1

**P1-1. 일시정지 + 설정 진입점**
- 문제: ESC 무동작, 옵션 진입 불가.
- 구체안: `update`의 play 분기에 `if(edge["escape"]) phase="paused"`. 일시정지 오버레이에 [계속]/[옵션]/[스테이지 선택]/[타이틀]. P0-2 옵션 패널을 여기서도 연다.

**P1-2. 진행 저장 신뢰성**
- 문제: 중간 진행 미저장 + 랜덤화로 이어하기 불일치(main.js:16, 61).
- 구체안: 저장에 `lastStage`/`hope`/수집 코어 id 추가하고 이어하기 시 해당 스테이지를 **고정 시드**로 재생성(makeLayout에 시드 인자). 최소한 "이어하기=마지막 클리어 다음 스테이지 시작"임을 버튼 부제로 명시(이미 main.js:1136에 STAGE 번호 표기 — 시드 일관성만 보강).

### P2

**P2-1. 색 비의존 표기** — 일지 범례·적 시야콘·조각에 모양/아이콘 동반(journal.js:529-531, main.js:648-657, 712). P0-2 색약 토글과 통합 가능.

**P2-2. 타이틀 오조작 방지** — "빈 공간 클릭=새 게임"을 명시적 [처음부터] 버튼 히트로만 한정하고, 이어하기 존재 시 빈 공간 클릭은 무시(main.js:279).

## 5. 결론

서사·연출·키보드 입력은 출시 수준에 근접했다. 그러나 **(1) 반응형/세이프에리어, (2) 접근성 옵션, (3) HUD 정보 정리** 세 P0를 처리하지 않으면 모바일/태블릿과 접근성 사용자에서 실패한다. 세 건 모두 캔버스 단일 렌더 구조 덕에 한 곳에서 배율/게이트 변수로 제어 가능하여, 비용 대비 효과가 크다.
